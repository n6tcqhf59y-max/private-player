# gitbb

只在这台 iPhone 上使用的文件夹。视频放进 gitbb 之后，会在本机加密存放，不会上传到开发者的服务器，也没有账号。用 Safari 打开站点后，添加到主屏幕。

发布路径是 GitHub Pages 的站点根目录（`https://n6tcqhf59y-max.github.io/private-player/`）。不要改成 `/web`，也不要清理浏览器里已经保存的网站数据。

锁屏和第一次进入时，界面就是一个叫 gitbb 的文件夹，里面是 0 到 9 号文件夹。不要把它理解成播放器名称。

## 第一次设置

1. 从 gitbb 走进六层文件夹。每一层都是 0–9。这六层连起来，就是以后打开 gitbb 的路径。
2. 再走一遍相同的路径。两次不一致就整条作废，重新选，不会告诉你哪一层不同。
3. 自己写一道问题，并填写答案。答案长短随意，请只有你自己知道。程序会去掉答案首尾的空格，再用来派生密钥。去掉之后如果什么都不剩，就无法使用。
4. 答案不明文保存。它会走和路径一样的 PBKDF2-SHA-256（60 万次），派生另一把密钥，把同一份数据密钥包起来。忘记六层路径后，答对这道问题还能解密原来的视频。

导入时不会删除相册或「文件」里的原视频。gitbb 只是另存一份加密副本。

## 忘记路径

连续把六层路径完整走错 5 次之后，才会出现你留下的那道问题。走到一半返回，不会计入这 5 次；走错时每一层看起来都一样，走完六层才提示打不开。

答对之后，可以重设一条六层路径。视频不用重新加密，仍然能解密。

答错会限制尝试次数：每错 5 次就暂停一段时间，而且一次比一次更长。取消、答错、锁定，都不会删除加密视频。

## 打开之后

全部视频都在这一个文件夹里。可以点「随机」，按随机顺序连续打开全部文件；一轮结束后会换一个顺序继续。点单个文件，则从它开始按当前排列往后打开。

## 自动锁定

解锁之后，10 分钟没有操作才会锁定。正在播放算作操作，不会在播放中途锁定。暂停或停止后，如果 10 分钟没有再操作，就会锁定。系统分享面板打开时不会锁定。切到后台时，如果当时没有在播放，也会锁定。

## 解密导出

解密导出只发生在本机：先解密出原视频，再交给 iPhone 的系统分享，由你自己存到「文件」、相册或你自己的网盘。网页应用不能直接写回相册或原来的文件目录。多个文件会一个接一个打开分享面板，因为一次分享多个文件在 iOS 上不可靠。

1. 点「选择」，勾选一个或多个文件，再点「解密导出」。也可以在单个文件的删除框里点「解密导出」。
2. 先阅读未加密警告。确认「开始导出」之后，才会在这台设备上解密。
3. 解密完成后点「保存到系统…」。这一步需要你再次点击，因为 Safari 和主屏幕应用只允许在点击当时打开系统分享。
4. 系统分享面板一旦打开，这个文件会立刻从 gitbb 里移除，即使你在面板里取消也一样。点「保存到系统…」之前取消，则加密副本还在。

## 安全说明

导出的是未加密原视频，不再受播放器密码或面容保护。拿到这个文件的人可以直接播放。

系统分享面板打开后，gitbb 里的加密副本已经移除。请自己到保存位置检查未加密文件是否真的留下了。取消分享面板也找不回 gitbb 里的那一份。

解密失败、密钥不对、分享面板没能打开，或在点「保存到系统…」之前取消、锁定，都不会移除加密副本。

gitbb 不会把导出的视频上传到开发者的云，也不会发给第三方服务器。系统分享面板里如果由你自己选择网盘，那是你在系统里保存，文件此时已经是未加密原视频。

加密仍然是 AES-256-GCM。数据密钥由路径派生的密钥包裹，派生算法是 PBKDF2-SHA-256，迭代次数 60 万，没有降低。找回问题的答案使用同一套派生参数，单独再包一层。

改版前如果已经在这台手机上设过更长的口令，锁定页底部可以「用原来的口令」打开，再到设置里改成六层路径并补上找回问题。`.ppb` 备份的文件格式没有换，仍然要用当时的路径或口令才能打开。

## 已安装的主屏幕应用

程序缓存版本是 `gitbb-v6`。站点不提供自制图标。程序文件优先从网络更新，离线时才用缓存；缓存里只有程序，没有用户视频。更新服务工作线程时，如果当时还停在文件夹或问题页，页面会自动刷新一次以加载新代码。正在打开文件或正在导出时不会为了更新而刷新。

## 开发者测试

测试只用合成的随机字节，不要把真实视频放进仓库或测试。

```bash
npm test
```

当前环境没有用真实 iPhone 验证系统分享面板。分享是否真正写入「文件」或相册，必须以你在手机上打开目标位置为准。
